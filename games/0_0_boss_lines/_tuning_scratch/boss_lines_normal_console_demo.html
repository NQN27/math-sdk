Two different "damage" numbers appear on this page — they mean different things. The Real counter-attack line above the HP bar, and each boss's real dam figure, come straight from game_config.py's boss roll formulas (±25% variance, exact same math as production) — that IS what the real game deals every spin the boss system is active, unconditionally, per game_bonus.py:405-407. The log's "HP -N (paced)" number and the boss HP bars moving are NOT that — they're a smoothed animation that spreads a whole stage-attempt's pre-decided total HP change evenly across however many spins were statistically drawn for it, so a single log line can show a small number like -6 late in a long attempt even though the real per-spin counter-attack (shown above) is much bigger. This trade-off exists because the outcome of each stage attempt (clear or die, and how many spins it takes) is drawn directly from the real engine's own measured per-stage hazard rate (normal_stage_reach_diagnostic.py, n=15000 per config) so the aggregate stats match reality — the per-spin animation is then reverse-fit to land on that real outcome smoothly, rather than mechanistically simulated hit-by-hit (which would require the actual paytable/reel data this context doesn't have). Run “Run 200 Sessions” and compare against the real ground-truth panel to see the aggregate match.
